# Fake News Explainability Platform

A full-stack web application that classifies a news article as **Fake** or **Real** and explains *why*:
the words that pushed the decision are highlighted inside the article (LIME and SHAP), together with a
confidence score, extracted keywords and the five most similar articles from the dataset.
It is a **decision-support tool, not a truth detector**.

WEX 428 project, Ostim Technical University. No external LLM API is used anywhere: all models are
trained locally with scikit-learn / XGBoost.

## What is inside

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite, React Router, Chart.js (separate User and Administrator interfaces) |
| Backend | FastAPI, SQLAlchemy ORM, JWT (PyJWT), bcrypt |
| Database | PostgreSQL 16 (tested) or SQLite (development) |
| NLP / ML | custom preprocessing, BoW / TF-IDF (+bigrams), Logistic Regression, linear SVM, Naive Bayes, Random Forest, XGBoost |
| Explainability | LIME (all models) and SHAP (Logistic Regression, XGBoost) |
| Similarity / keywords | TF-IDF + cosine similarity (top 5); TF-IDF or RAKE keywords |
| Deployment | Docker Compose (db + backend + nginx/frontend), GitHub Actions CI |

## Quick start (Docker)

```bash
cp .env.example .env            # then edit: POSTGRES_PASSWORD, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
mkdir dataset                   # put Fake.csv and True.csv in ./dataset
docker compose up -d --build
docker compose exec backend python /srv/scripts/bootstrap.py --data /data --demo-user
```

Open <http://localhost:8080>. The bootstrap command imports the dataset (about 1 minute), trains the five
models (about 8 minutes on one CPU core, XGBoost is the slowest) and activates Logistic Regression.
Sign in with the administrator from your `.env`, or with `demo@example.com / Demo12345`
(created only by `--demo-user`; delete it for real deployments).

Interactive API documentation: <http://localhost:8000/docs>.

## Local development (no Docker)

```bash
# backend
cd backend && python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
export JWT_SECRET=change-me ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD=Admin12345   # SQLite is the default DB
python ../scripts/bootstrap.py --data /path/to/dataset --demo-user
uvicorn app.main:app --port 8000

# frontend (second terminal)
cd frontend && npm install && npm run dev        # http://localhost:5173, proxies /api to :8000
```

To use PostgreSQL locally set `DATABASE_URL=postgresql+psycopg2://user:pass@localhost/dbname`.

## Using the platform

**User:** register / log in, paste text or upload `.txt` / `.pdf`, read the verdict, confidence, highlighted
words (LIME / SHAP), keywords and similar articles; search, delete and export history (PDF / CSV); edit profile,
change password, theme.
**Administrator** (`/admin`): dashboard and charts, users, dataset import with preview / validation / duplicate
detection / progress, news article and category management, model training / retraining / comparison /
activation (only one active model, enforced by a database index), analytics, explainability monitoring,
stop-word list, keyword dictionary, settings, system logs, PDF / CSV reports.

Demo articles that the model **never trained on** are in `docs/demo_articles/` (generated by
`scripts/make_demo_articles.py`; one of them is a deliberate model mistake for discussion).

## Tests

```bash
cd backend && python -m pytest -q                       # 22 API tests, SQLite
DATABASE_URL=postgresql+psycopg2://fn:fnpass@localhost/fn_test python -m pytest -q   # same suite on PostgreSQL
python scripts/e2e_ui.py                                # browser test (Playwright) with backend :8000 + frontend :5173
```

The API tests use a 1,400-article sample of the real dataset; set `FN_DATA_DIR` to the folder that contains
`Fake.csv` and `True.csv`. They are skipped when the data is absent.

## Reproducing the experiments

```bash
python scripts/run_experiments.py prep && python scripts/run_experiments.py exp_a   # also: baseline, exp_b, exp_c
```
Results are written to `docs/experiments/results.json`. See `docs/leakage_analysis.md`.

## Security measures

bcrypt password hashing (SHA-256 pre-hash so long passphrases are not truncated), JWT with server-side revocation on
logout, role-based access control checked against the database on every admin request, login throttling
(5 failures / 10 min), parameterised ORM queries only (no SQL injection), React escaping and no `dangerouslySetInnerHTML`
(XSS), upload validation by extension, size and file signature, secrets only in environment variables,
non-root container user, security headers.

## Known limitations (please read)

* **The classifier learns the style of two news sources.** After removing the Reuters fingerprint accuracy is still
  ~98.6%, because Fake and Real articles in this dataset also differ in writing style. Expect lower performance on
  other publishers. See `docs/leakage_analysis.md`.
* A confident prediction can be wrong (see `docs/demo_articles/mistake.txt`).
* SHAP is available for Logistic Regression and XGBoost; LIME works for every model.
* The interface language and e-mail-notification preferences are stored but not yet used (the UI is English only,
  no e-mails are sent unless SMTP is configured, and then only for password reset). Not implemented: refresh tokens
  (optional in the assignment), Word2Vec / FastText / BM25, cloud deployment.
* Password-reset links are written to the backend log when SMTP is not configured.
* Docker images were written but **not built in the development environment** (no Docker there); the backend
  suite was run on PostgreSQL 16 and SQLite, and the frontend in headless Chromium.
